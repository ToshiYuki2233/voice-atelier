# 規則ベースの声の尺度モデル

確認・実装日時：**2026-09-13 14:46 JST**（Windows 11、Node 24.14.0、Chrome 152.0.7977.83）。

学習済みの重みを使わず、公開研究で定義が確立した音響特徴量を、人が決めた固定の規則で四つの尺度に写す方式を実装した。**モデルファイルはなく、学習・微調整・個人適応・重みの保存を一切行わない。** 利用者の声は解析中のメモリにのみ存在し、停止時に消去する。

これは感情分類器ではない。喜怒哀楽のラベルも、演技力の点数も出さない。出すのは声の物理量の向きだけである。

## 採用理由

別途検証したONNX版wav2vec2は、日本語24例で一致7/24、推論に約2秒、無音・正弦波・雑音のすべてに `sad` を返した（[検証記録](EMOTION-VALIDATION.md)）。本番で光を声に追従させる用途に対して、応答速度と誤反応の両方が不足している。規則ベースはこの二点を構造的に解消し、加えて同梱モデル約90 MBとランタイム約14 MB、およびモデルのライセンス条件が不要になる。

代償として、この方式は感情を推定しない。感情の解釈は審査員と演者に委ねる設計とした。

## 測っているもの

`public/spectrum.js` に実装。括弧内は原典の定義そのもの。

| 量 | 定義 | 実装 |
| --- | --- | --- |
| Alpha Ratio | 50–1000 Hzの総和エネルギー ÷ 1–5 kHzの総和エネルギー | `measureSpectralBalance` |
| Hammarberg Index | 0–2 kHzの最強ピーク ÷ 2–5 kHzの最強ピーク | 同上 |
| Spectral Slope | 0–500 Hzおよび500–1500 Hzの対数パワースペクトルの回帰傾き | 同上 |
| Pitch | 27.5 Hzを半音0とする半音尺度上の対数F0。半音1未満は1にクリップ | `toSemitone` |
| Jitter | 連続するF0周期長の変動 | `measureVoiceQuality` |
| Shimmer | 連続するF0周期のピーク振幅の差 | 同上 |
| HNR | 調波成分のエネルギーと雑音的成分のエネルギーの比 | 同上 |
| 音の山の数 | 1秒あたりのラウドネスのピーク数 | `expression-model.js` の `countPeaks` |

スペクトル系は原典と同じく20 msのHamming窓・10 ms間隔・ゼロ埋めで求め、窓ごとの値の算術平均を返す。

### 原典との相違（eGeMAPS準拠の数値ではない）

以下は意図的な相違であり、**本実装の出力がopenSMILEのeGeMAPS出力と一致することは確認していない**。一致を主張しない。

- ラウドネスは聴覚スペクトルではなくRMS（dBFS）で代用している。原典の定義とは別物。
- F0は原典のSHSではなく、既存実装のYIN系（累積平均正規化差分）を使う。
- F0・jitter・shimmer・HNRは、原典の60 ms窓ではなく解析フレーム（48 kHzで4096点＝約85 ms）全体から求める。
- 平滑化は3フレーム移動平均ではなく、1.2秒窓の中央値を使う。
- 統計量は発話全体の算術平均・変動係数ではなく、移動窓の中央値と分位点を使う。生放送的な表示のため。
- ゼロ埋めの倍率（窓長の2倍以上の2のべき乗）は本実装の選択。
- フォルマント、MFCC、調波差はまだ実装していない。

## 四つの尺度

`public/expression-model.js`。感情語を避け、測っているものの名前を付けた。

| 軸 | 表示名 | 構成要素 |
| --- | --- | --- |
| power | 勢い | 半音F0、レベル（dBFS）、音の山の数／秒 |
| edge | 張り | Alpha Ratio（符号反転）、Hammarberg Index（符号反転） |
| waver | 揺れ | jitter、shimmer、HNR（符号反転） |
| spread | 幅 | 直近1.2秒の高さの振れ幅と大きさの振れ幅（各p90−p10） |

特徴量の系統を軸ごとに分けてあるため、軸どうしが同じ量を共有しない。設計時は「怒りと喜びのように、どちらも勢いが強い表現を張りの軸で区別できる」と想定していたが、**後述の日本語24例ではこの想定は支持されなかった（2/4）**。現時点で未解決の弱点である。

### 軸の出し方と、測れている割合

各軸は構成要素を等しい重み（すべて1）で合計するが、**割るのは測れた要素の重みではなく、全要素の重みである。**

```
軸   = Σ(重み × 符号 × z、測れた要素だけ) ÷ Σ(重み、全要素)
割合 = Σ(重み、測れた要素) ÷ Σ(重み、全要素)
```

測れない要素は何も足さないため、残りの要素が欠測分を代表することはない。結果として軸の値は自動的に中央へ寄り、**|軸の値| ≤ 割合** が常に成り立つ。持っているデータで裏づけられる以上の変化量を主張しない、という保証である（試験で全フレーム検査している）。

測れた要素が一つもない軸は `null` を返し、画面では「—」と表示する。**0.00（測れていて、いつもの範囲）とは意味が違うため、必ず見分けられるようにしている。** 「揺れのない落ち着いた声」と「測定不能」が同じに見えてはいけない。

この割合は表示にも出す。値が中央寄りなのが「声が平常だから」なのか「測れていないから」なのかを、利用者が区別できるようにするため。

### 係数について

**各軸は構成要素の単純平均である。** 重み付けの比率は等分で固定し、録音データに合わせた調整を行っていない。比率を変えれば、それはどこかのデータへの当てはめ（学習の一種）になるため、意図的に等分のままにしている。符号（どちらの向きが「強い」か）だけが文献由来の設計判断である。

`FLOORS` の各値は「これ未満のばらつきは差と見なさない」という分解能の下限で、当てはめによる推定値ではない。

### 基準の取り方

絶対値ではなく、**直前12秒の自分の声と比べた向き**を表示する。各特徴量を移動窓の中央値とMAD（中央絶対偏差）で正規化し、±1に収める。

これは移動平均と同種の「その場の正規化」であり、次のいずれも行わない。

- 話者プロファイルの作成・保存
- 校正ステップやモデル重みの更新
- セッションをまたぐ蓄積（`reset()` が全フレームを破棄し、停止のたびに呼ばれる）

`AGENTS.md` が禁じる「個人適応」に当たるかは解釈の余地がある。本実装は明示的な校正手順を設けず、窓が過ぎた値は捨てる構成にしてこの論点を回避した。**この線引きの是非は開発者（利用者）の確認事項として残す。**

### 判定しない場合

次のいずれかで、軸を一切表示せず理由を書く。

| 条件 | 表示 |
| --- | --- |
| レベルが −50 dBFS 未満 | 入力が静かすぎます。声を出すと表示されます。 |
| 直近1.5秒に有声フレームが一つもない | 声（周期的な音）を検出していません。 |
| 開始から4秒未満 | 声の範囲を測っています。数秒お待ちください。 |

**有声の要求は軸ごとに異なる。** 「直近1.2秒の有声率25%未満なら四軸すべて非表示」という当初の関門は、基本周波数を必要としない要素まで巻き添えで消していたため廃止した。代わりに、(a) 直近1.5秒に声が一度もなければ全体を非表示（ドアの音や定常雑音に反応させないため。1.5秒は表示側の `PitchReadout` が既に採用している保持時間に合わせた）、(b) それ以外は要素ごとに測れるものだけを使う、という二段構えにしている。レベルと音の山の数は無声区間でも測れるので、勢いと幅は子音や息継ぎの間も残る。

**これは設計の中心である。** 先行検証で分類器が無音・正弦波・雑音のすべてに `sad` を返した問題は、「一番大きい出力を必ず何かのラベルにする」構造から生じる。本モデルは入力が条件を満たさなければ何も出さない。

## 検証結果

`npm.cmd test` は34件すべて通過（新規21件）。合成信号で単調性を確認しているため、分類器では書けない種類の試験ができている。

- Alpha Ratioは、高域成分を0→0.1→0.3→0.6→1.0と足すと単調に低下する。
- HNRは、雑音を0→0.02→0.08→0.2と足すと単調に低下する。
- jitter・shimmerは、周期長・振幅を既知の量だけ交互に変えた信号から、その変動を復元する。
- 無音・短すぎる入力・NaN・低すぎるサンプリングレートには値を返さない（代用値を作らない）。
- モデル側：軸は測れている割合を超える変化量を主張しない（|軸の値| ≤ 割合）。300フレームの全区間で検査。
- モデル側：0.8秒の無声区間は1.2秒窓がまたぐので張りが残る。1.3秒続くと張りと揺れは `null` になり、基本周波数を必要としない勢い（割合2/3）と幅（割合1/2）だけが残る。
- モデル側：最後の有声から1.5秒を超えると全体が非表示に戻る。
- 同じ入力に対する出力は完全一致する（決定的）。
- モデル側：無音は `unavailable`、大きいが非周期な音も `unavailable`、開始4秒未満は `warming`。
- モデル側：大きく高い声で勢いが、高域寄りの声で張りだけが、乱れた周期で揺れが、広い振れ幅で幅が上がる。張りを動かしても勢いは0.25未満に留まる（軸の分離）。
- モデル側：変化のない声では全軸が0.35未満に留まり、「いつもの範囲です。」と表示する。

`npm.cmd run test:browser` は13項目通過。実ブラウザで確認した内容：

- Chromiumの疑似マイク（ビープ音。大きいが非周期）を6秒間入力し続けても、四軸は一度も数値にならない。表示されたのは「入力が静かすぎます。」と「声（周期的な音）を検出していません。」の2種類だけで、いずれも理由を述べた非表示状態である。**設計どおりの拒否がブラウザ上で再現した。**
- ページ内で生成した合成音（196 Hz鋸歯状波＋ビブラート＋音量のうねり）では四軸すべてが数値になる。3回の実行での記録は、勢い −0.33〜−0.35、張り ±0.00、揺れ −0.00〜+0.04、幅 −0.02〜−0.08。合成音は生成した試験信号であり、録音した人の声ではない。
- 停止すると四軸は「—」に戻る。
- 計測パネルを開いた状態で、幅1180・820・390 CSSピクセルのいずれでも横方向のはみ出しがない。
- 未捕捉のJavaScript例外なし。ページからの通信はローカルのGETのみ。Cookie・localStorage・sessionStorage・IndexedDBへの書き込みなし。キャッシュはアプリ資産13件のみ。

## 日本語24例での測定（2026-09-13）

分類器と同じJVNVの24例・中央3秒・同じ選定規則で測った。`npm.cmd run lab:rule` で再実行できる。再実行して同じ結果になることを確認済み（決定的）。

**判定条件は音声を取得する前に固定し、結果を見てから変えていない。** 条件は `scripts/emotion-lab/rule-run.mjs` の `PREDICTIONS` にそのまま残してある。話者ごとに別々に数えるのは、このモデルが他人ではなく自分自身と比べる設計だからである。各話者の6件をその話者の比較範囲とした。

| 予測 | 初版 | 現在 |
| --- | --- | --- |
| P1 悲しみが、その話者の6件中で勢いが最も低い | 2/4（測定不能1） | 2/4 |
| P2 怒りの勢いが悲しみより高い | 3/4（測定不能1） | **4/4** |
| P3 怒りの張りが喜びより高い | 2/4 | **1/4** |
| P4 怒りの張りが悲しみより高い | 3/4（測定不能1） | **2/4** |
| P5 恐れの揺れが平均より高い | 3/4 | **4/4** |
| P6 喜びの幅が悲しみより広い | 2/4（測定不能1） | **3/4** |
| 合計 | 15成立／測定可20枠 | 16成立／測定可**24**枠 |

「初版」は軸ごとの可否分離と重み付けを入れる前。「現在」は入れた後。予測そのものは最初に固定したまま変えていない。

### 何が良くなったか

**測定不能が4枠から0枠に減った。** 初版ではM2の悲しみ（有声7%）が四軸すべて測定不能だったが、現在は勢い −0.50、張り +1.12、揺れ −0.73、幅 −0.56（幅のみ割合50%）を返す。これが今回の変更で狙った効果であり、達成できている。

勢い（P2 4/4）と揺れ（P5 4/4）は、測定できた全話者で予測どおりになった。

### 何が悪くなったか — 張りの軸は機能していない

**P3が2/4から1/4、P4が3/4から2/4に下がった。** 怒りと喜び、怒りと悲しみのどちらも、張りの軸では偶然以下である。**この軸は現時点で機能していないと考えるべきである。**

途中で一度、原因の見当をつけて実装を直している。初版はAlpha RatioとHammarberg Indexを「音が鳴っているフレーム」すべてで計算していた。しかし摩擦音や息の高域エネルギーは声の力みではなく子音を表しており、両者を平均すると張りの意味が静かにすり替わる。実データでもM2の悲しみ（有声7%、ほぼ息）が張り最高値 +1.82 を示しており、この誤りが出ていた。**GeMAPSも有声区間と無声区間のスペクトル統計を別々のパラメータとして定義している**ため、混ぜていたのは原典からの逸脱でもあった。現在は有声フレームのみで計算している（1.2秒窓の中央値なので、短い無声区間はまたぐ）。

この修正は原典の定義を根拠にしたもので、成績を上げるために数値を合わせたのではない。**そして実際、修正後も張りの成績は上がらなかった（P3は2/4→0/4→1/4と動いた）。** 隠さず記録する。

**ここで張りの軸への変更は止めた。** これ以上この24例を見ながら要素や重みを触れば、それは当てはめ（学習の一種）になる。次に触るなら、先に設計を決めて文書に書き、それから測る順序を守る必要がある。

### 数字の読み方の注意

24枠中16枠成立で、偶然の期待値は約11枠（P1は1/6、他は1/2）。**これは有意性の検定ではない。** 話者4名、各感情1件ずつ、観測も独立でない。16対11を根拠に有効性を主張しない。

同じ24例に対する分類器の一致は7/24だったが、**測っているものが違うため優劣として並べてはいけない。** 分類器は感情名を当てにいき、こちらは軸の向きが期待どおりかを見ている。

この測定は3秒のクリップ全体の中央値に対するものなので、**実際の画面が何秒おきに「—」になるかは測れていない。** 報告中の割合（ほぼ100%）はクリップ単位の集計値であり、本番の表示の途切れにくさを表す数字ではない。

### 最大の問題：有声と判定されるフレームが少ない

| 指標 | 平均（24例） |
| --- | --- |
| 音量が閾値以上（−50 dBFS以上）のフレーム | **79%** |
| 周期性しきい値0.12（本アプリの現在値）で有声 | **30%** |
| 同 0.20 | 44% |
| 同 0.30 | 53% |
| 同 0.45 | 63% |

音としては79%が鳴っているのに、有声と判定されるのは30%しかない。差の大半は無音ではなく**周期性しきい値の厳しさ**によるもので、0.30まで緩めると53%に増える。

最悪の例はM2の悲しみで、30フレーム中2フレーム（7%）しか有声にならず、**四軸すべてが測定不能**になった。上表の「測定不能4枠」はすべてこの1件に由来する。

**これは検証手順の問題ではなく、本番アプリに直接効く問題である。** 現在の実装は直近1.2秒の有声フレームが25%未満なら四軸すべてを非表示にするので、実際の演技では「声を検出していません」が頻繁に出る可能性が高い。オーディション本番で画面が頻繁に空になるのは、壊れて見える。

しきい値を数値合わせで緩めるのは、この24例への当てはめになるので行っていない。構造的な対処として次の二つが考えられる（いずれも未実装）。

1. **軸ごとに可否を分ける。** 張りの軸（Alpha Ratio、Hammarberg Index）は基本周波数を必要としない。勢いも3要素中2要素は不要。厳密に有声が要るのは揺れの軸だけである。現在の「全軸まとめて非表示」は粗すぎる。
2. **短い無声区間をまたぐ。** 表示側は既に `PitchReadout` が直前値を最大1.5秒保持しているが、モデルはフレーム単位の生の値しか受け取っていない。語中の短い切れ目を埋める処理を、保持であることを明示したうえで入れる余地がある。

## ステージの光への反映（2026-09-13）

感情スコアを数値で出す案は採らなかった。理由は作法ではなく実測で、**表示できるだけの精度の感情推定が手元にない**ため（分類器7/24、張りの軸は偶然以下）。怒りを演じている最中に「悲しみ」と出れば、審査員の前で機械が演技を誤読したことになる。

代わりに色で示す。色は数値と違って精度を主張しないため、精度が足りない対象には適している。**ただし色に感情の名前は割り当てない。** 凡例は「勢い」であり、「赤＝怒り」ではない。審査員はラベルを必要としておらず、演技に合わせて光が変わること自体が見せ場である。

| 光の要素 | 連動するもの |
| --- | --- |
| 広がり | 入力レベル（従来どおり） |
| 上下位置 | 推定した基本周波数（従来どおり） |
| **色（寒色⇄暖色）** | **勢いの軸**（新規。従来は高さが色を決めていた） |
| 色の濃さ | 測れている割合 |
| 輪郭のわずかな揺らぎ | 揺れの軸 |

**張りの軸は光に使っていない。** 日本語24例で予測を満たさなかったため、意図的に外している。検証で支持されなかった軸を本番の見せ場に載せない、という判断である。

### 点滅の測定と対処

フレーム単位で数えたところ、3秒クリップでは**色が出ているのは平均55%、色あり／なしの切り替えが平均0.9回/秒**だった。毎秒1回近く色が出入りするのは、演技の背景として落ち着かない。最悪はM1の驚きと嫌悪で、色が出るのは17%だった。

この数字は3秒のクリップを毎回ゼロから始めた値なので、移動窓が埋まるまでの最初の約1秒が必ず非表示になる分、**実際の連続使用より悲観的である。** それでも切り替えの多さは実害があるため、表示側に時定数500 msの追従を入れた（`LightSmoother`）。

- 読み取れている間だけ色を追う。読めない間は**色を保持したまま明るさだけ落とす**ので、途切れが「色が変わった」ではなく「光が弱まった」と見える。
- **平滑化するのは絵だけで、数値パネルは生の値のまま。** 測定値を隠したり作ったりはしていない。
- 1フレームの欠測で色が振れないことを試験で確認している（20フレーム後に1フレーム欠測させても色相の変化は5未満）。

平滑化後の点滅の程度は再測定していない。実測が要る。

## 未実施・未確認

- **日本語24例の測定は実施したが、規模が小さく結論にならない。** 4話者・各感情1件では有意性を論じられない。話者数を増やす、感情ごとの件数を増やす、中央3秒を人が聴いて再評価する、のいずれも未実施。この規模のまま「日本語の演じ分けに有効」と主張しない。
- **張りの軸が機能していない（P3 1/4、P4 2/4）。** 要素の選び直しか、この軸の取り下げが要る。ただし次に触るときは、先に設計を決めて文書化し、それから測る順序を守ること。
- **有声判定率の低さ（音が鳴っている79%に対し有声30%）自体は未解決。** 軸ごとの可否分離で影響は和らげたが、周期性の検出そのものは改善していない。**実際の画面が何秒おきに「—」になるかは測定していない。** フレーム単位の可否を数える診断が要る。
- **iPad実機で未検証。** 読み込み時間、発声から表示までの遅れ、発熱、連続動作は測っていない。FFTがフレームごとに7回走る負荷の実測も未了。
- 本物の声で未検証。開発者の声を含め、実マイク入力での確認を行っていない。
- **平滑化を入れた後の点滅の程度を再測定していない。** 上の0.9回/秒は平滑化前の値。
- 色の見え方をiPadの画面・会場の照明で確認していない。寒色と暖色の差が審査員の位置から分かるかは未検証。
- 自動ゲイン制御が有効な端末ではレベル軸が、ノイズ抑制が有効な端末ではAlpha RatioとHNRが影響を受ける。現在は実際の設定を画面に表示しているだけで、軸ごとに信頼度を下げる処理は入れていない。
- フォルマント、MFCC、調波差は未実装。
- 特許の調査は行っていない。
