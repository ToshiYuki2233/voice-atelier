# セキュリティ確認（機密性・完全性・可用性）

確認日：2026-09-15。対象は GitHub の公開リポジトリ `ToshiYuki2233/voice-atelier` と、GitHub Pages で配信している iPad 向けアプリ（https://toshiyuki2233.github.io/voice-atelier/）。「確認済み」は実際に調べた事実だけを指す。iPad 実機での確認は行っていない。

## 守るもの

| 資産 | 例 |
| --- | --- |
| 利用者の声 | マイク入力、測定値 |
| 利用者が入力した台詞 | オーディション用の一節 |
| アプリの中身 | 配信されるコード。改ざんされると声の扱いが変わりうる |
| 本番で使えること | オーディション会場で起動し、途中で止まらないこと |

## 機密性（Confidentiality）

| 項目 | 状態 | 根拠 |
| --- | --- | --- |
| 声・測定値を外部へ送らない | 確認済み | 送信処理がない。CSP で `connect-src 'self'` に限定。ブラウザ検証でページの通信がローカルの GET のみ、WebSocket なし |
| 声・台詞を保存しない | 確認済み | Cookie・localStorage・sessionStorage・IndexedDB への書き込みなし（ブラウザ検証）。キャッシュはアプリ資産13件のみ。台詞の入力欄はアプリのコードから読み出していない |
| リポジトリに秘密情報がない | 確認済み | 履歴全体でトークン・秘密鍵・Gmail アドレスを検索して0件。証明書 `.certs/` は除外。シークレットスキャンとプッシュ保護が有効 |
| 個人のメールアドレスの露出 | 対処済み | コミットは GitHub の非公開用アドレス |
| 通信の暗号化 | 確認済み | Pages で HTTPS 強制、HSTS ヘッダーあり |
| 同じオリジンを共有する他サイト | 現状なし | `toshiyuki2233.github.io` で Pages を公開しているのはこのリポジトリだけ |
| GitHub 側のアクセス記録 | 残る | アプリは何も送らないが、ページを開いた際の IP アドレス等は GitHub のサーバーに記録されうる |

**注意：** マイクの許可はオリジン（`toshiyuki2233.github.io`）単位で iPad に記憶される。今後この GitHub アカウントで別のリポジトリを Pages 公開すると、そのサイトも同じオリジンになり、このアプリに与えたマイク許可を共有しうる。他の Pages サイトを作る場合は、信頼できる内容に限るか、別アカウント／独自ドメインを使う。

## 完全性（Integrity）

| 項目 | 状態 | 根拠 |
| --- | --- | --- |
| 外部スクリプトの混入 | 防止 | 外部CDN・外部フォントなし。CSP `script-src 'self'`、インラインスクリプトなし |
| HTML/スクリプト注入（XSS） | 経路なし | `innerHTML`・`document.write`・`eval` 等を使っていない。入力された台詞は画面に描き戻さない |
| 他サイトへの埋め込み（クリックジャッキング） | 対処済み | Pages は埋め込み禁止ヘッダーを送れないため、埋め込まれた状態ではマイクを開始しない処理を追加 |
| CI の供給網 | 対処済み | 外部アクションをコミット SHA に固定。ジョブごとに最小権限（テストは読み取りのみ）。Dependabot で更新を PR として提示 |
| 壊れた版の公開 | 防止 | テストが通った場合だけ公開。失敗時は直前の正常な版が残る |
| コードの脆弱性 | 0件 | CodeQL のコードスキャンを有効化、警告0件。npm の脆弱性0件 |
| リポジトリへの書き込み権限 | 所有者のみ | 共同作業者なし |
| GitHub アカウントの二要素認証 | **未確認** | 使用中のトークンの権限では確認できなかった。GitHub の設定画面で有効か確認すること |
| ブランチ保護 | 未設定（意図的） | 所有者1人のため。有効にすると自分の直接 push も制限される。二要素認証の方が効果が大きい |

**残る危険：** このPCの GitHub ログイン（Windows の資格情報に保存）が盗まれると、改ざんした版を公開できてしまう。PC のアカウント保護と GitHub の二要素認証が最後の砦になる。

## 可用性（Availability）

| 項目 | 状態 | 根拠 |
| --- | --- | --- |
| 会場にネットがない | 対策あり | Service Worker が全資産を保存し、オフライン準備完了を表示（iPad 画面サイズを再現したブラウザで確認。実機未確認） |
| Safari の保存データ自動削除 | **ホーム画面に追加で回避** | Safari ではサイトを7日間（ブラウザを使った日数）操作しないと、Service Worker 登録を含む保存データが削除される。ホーム画面に追加した Web アプリはこの対象外（WebKit の公式説明） |
| 本番中に画面が自動ロックされる | 対処済み | 画面が隠れるとマイクを止める仕様のため、マイク使用中だけ画面のスリープを防ぐ処理を追加。Safari 16.4 以降で対応、ホーム画面の Web アプリでは iPadOS 18.4 以降。非対応・拒否時は画面に「自動ロックを『なし』に」と表示 |
| GitHub の障害・Pages 停止 | 影響は初回のみ | 一度保存済みなら、端末内のキャッシュで起動できる |
| 更新の反映 | 最大10分程度遅れる | Pages の `Cache-Control: max-age=600` |
| 着信・他アプリでの中断 | 停止して案内 | 中断時はマイクを止め、再開方法を表示（ブラウザで模擬確認） |

## 本番前にやること（iPad）

1. 前日までに、ネットにつながった状態で Safari からアプリを開き、「ホーム画面に追加」する。
2. ホーム画面のアイコンから開き、「オフライン準備完了」と表示されることを確認する。
3. 同じくホーム画面から「マイクを開始」し、マイクの許可を済ませる。表示に「画面の自動ロック防止 有効」と出るか確認する。出なければ「設定 → 画面表示と明るさ → 自動ロック」を「なし」にする。
4. 機内モードにして、ホーム画面から起動できることを確認する。
5. GitHub の設定で二要素認証が有効か確認する。
