# 声のアトリエ

iPadを審査員に見せ、声の演じ分けを光の変化で補助する、本番の自己アピール用PWAです。Windowsで開発・起動できます。

## 本番で何をするか

1. 「マイクを開始」を押し、iPadを審査員から見える位置に置く。
2. 「声の演じ分けを、光と一緒にご覧ください」と紹介して「本番表示へ」を押す。
3. 台詞を、静かに、ささやくように → 明るく、弾ませて → 強く、言い切る の順に演じる。「次の指示」は自分で押して切り替える。台詞は画面上で書き換えられるので、ご自身のオーディション用の一節を入れておく。既定は「わかりました。」で、ページを開き直すと既定に戻る。
4. 声の大きさが光の広がりに、推定した高さが光の上下に、計測した「勢い」が光の色（寒色⇄暖色）に反映される。光は立ち上がりが速く戻りが遅いので、言葉の切れ目で消えない。外側の薄い輪はその演じ方での最大の広がりを数秒保持するので、次の演じ方と見比べられる。最後に「停止」を押す。

お題は手動の演出指示で、アプリが感情を検出した結果ではありません。色は計測した「勢い」の目印で、喜怒哀楽を表しません。色に感情の名前は割り当てていません。喜怒哀楽を分類するモデルは引き続き未導入です。「波形・計測値を見る」の中に、学習を使わない規則ベースの「声の四つの尺度」（勢い・張り・揺れ・幅）があります。光に使っているのは大きさ・高さ・勢い（と、輪郭のわずかな揺らぎに揺れ）で、張りと幅は光に使っていません。「本番表示」はページ内で操作とステージを大きく表示するモードです。ブラウザのアドレスバーを消す機能ではありません。「通常表示へ」またはEscで戻れます。

高さが表示されるかの操作確認には「あー」と2秒ほど発声します。言葉の切れ目で消えて読めなくなることを抑えるため、実際の検出値を最大1.5秒、「直前の検出値」と明記して残します。停止時には直ちに消去します。「波形・計測値を見る」で数値を確認できます。

## iPadで開く（GitHub Pages）

**https://toshiyuki2233.github.io/voice-atelier/**

1. iPadの Safari で上のURLを開き、「マイクを開始」でマイクの使用を許可する。
2. 「オフライン準備完了」と表示されたら、共有メニューの「ホーム画面に追加」でアプリとして置ける。
3. 更新後に古い画面が出たら、このアプリのタブとホーム画面のアプリをすべて閉じて開き直す。
4. 本番前の準備（ホーム画面への追加、オフライン起動、自動ロック）は [セキュリティ確認](docs/SECURITY-CIA.md) の「本番前にやること」を参照。Safari で7日間開かないと保存データが消えることがあるため、ホーム画面に追加して使う。

`main` に push すると、テストが通った場合だけ `public/` の中身が自動で公開されます。README や docs はサイトとしては配信されません。GitHub Pages のサーバーには GitHub 側のアクセスログが残りますが、アプリ自体は音声・台詞・測定値を送信しません。**iPad 実機でのマイク許可、音質、光の見え方、オフライン起動は未確認です。** 確認済みなのは Windows 上の Chrome で iPad の画面サイズを再現した表示と、疑似マイクでの動作だけです。

## すでに起動している画面の更新

PowerShellのサーバーはそのままで構いません。アプリのページを一度再読み込みし、数秒待ってから、このアプリを開いているタブやPWAをすべて閉じ、同じURLをもう一度開いてください。見出しが「ひとつの声で、場面を変える。」なら新しい画面です。オフライン用の旧版が残ることがあるため、開き直しが必要です。

## 実装した段階

1. AGENTS.mdに開発条件を記録。
2. マイクの開始／停止、許可拒否・中断への対応。
3. 実際の入力波形、RMS入力レベル（dBFS）、周期性から推定した基本周波数（Hz）。
4. アプリ資産だけをキャッシュするService Worker、マニフェスト、iPad用アイコン。
5. audEERING候補モデルの公式ONNX配布・利用条件を調査。**本番アプリにはモデルと推論ランタイムは未導入**。
6. 本番表示、声の特徴に反応する光、手動で切り替える演じ方のお題、直前の高さの短時間表示。
7. 別の開発用ページで感情モデルを実検証。公開日本語24例では一致7/24で、本番採用は見送り。[検証結果と再実行手順](docs/EMOTION-VALIDATION.md)。利用者の声は使っていません。
8. 学習を使わない規則ベースの「声の四つの尺度」を実装。公開研究で定義された音響特徴量を固定の規則で計算します。モデルファイル・学習・微調整・個人適応はありません。[規則・権利確認・検証結果](docs/EMOTION-RULE-MODEL.md)。
9. 同じ日本語24例で測定。勢いと揺れの軸は予測どおりでしたが（各4/4）、**張りの軸は機能していません**（怒りと喜びの区別は1/4）。[測定結果](docs/EMOTION-RULE-MODEL.md)。
10. 軸ごとに測れるものだけを使う方式に変更。測れない要素がある軸は、その分だけ値が中央に寄り、「測れている割合」を併記します。測れる要素が一つもない軸は「—」と表示し、0.00（測れていて、いつもの範囲）と区別します。四つを合計した総合点は出しません。

入力した台詞は端末外へ送らず、保存もしません。感情の分類、演技力・魅力度の採点、録音、結果履歴、アクセス解析はありません。四つの尺度は声の物理量の向きで、感情でも点数でもありません。無音や周期の不明瞭な入力で仮の高さを補いません。PCは静的ファイルを配るだけで、音声解析はiPad上で行います。

## Windowsですぐ起動

Node.js 22以降を用意します（開発時は24.14.0）。PowerShellでこのフォルダーを開き、実行します。通常のアプリ起動には npm install は不要です。感情モデルの開発検証だけは、別途開発用ライブラリを使います。

~~~powershell
npm.cmd start
~~~

WindowsのEdge／Chromeで **http://localhost:5173** を開き、「マイクを開始」を押して許可します。終了はPowerShellで Ctrl+C。npm.ps1 の実行ポリシーの影響を避けるため npm.cmd を使っています。

~~~powershell
npm.cmd run check
npm.cmd test
~~~

追加のブラウザ検証（WindowsのChromeまたはEdgeを使用）：

~~~powershell
npm.cmd run test:browser
~~~

独立した非表示ブラウザと仮想マイクで検証します。実マイクは使いません。.test-browser/ にテスト専用プロファイルを作り、docs/preview.png と docs/presentation.png に未計測の待機画面を保存します。テストコード内のCDP通信・ストリーム参照は検証専用で、public/ のアプリには含まれません。

HTMLのダブルクリック（file://）では起動しないでください。localhostのHTTPはWindows自身の確認用です。iPadから http://PCのIP:5173 にアクセスする方式は使えません。マイクの利用には安全なコンテキストが必要です。[getUserMedia公式リファレンス](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

## WindowsからiPadへHTTPSで配信

同じ信頼できるWi-FiにPCとiPadを接続してください。初回だけPCからアプリ資産を取得し、その後はオフライン起動を試せます。

1. [mkcert公式のWindows手順](https://github.com/FiloSottile/mkcert#installation)に従いmkcertをインストールします。公式ReleasesのWindowsバイナリを取得してPATHに置く方法もあります。
2. PowerShellで以下を実行します。IPv4は ipconfig で調べ、例の 192.168.1.20 を自分のPCのWi-Fi IPv4に置き換えてください。

~~~powershell
ipconfig
mkcert -install
New-Item -ItemType Directory -Path .certs -Force
mkcert -cert-file .certs/dev.pem -key-file .certs/dev-key.pem localhost 127.0.0.1 192.168.1.20
mkcert -CAROOT
~~~

3. 最後に表示されたフォルダー内の **rootCA.pemだけ** をiPadへ転送し、証明書プロファイルとしてインストールします。必要なら転送用コピーの拡張子を .crt にします。自分が作成したCA証明書であることを確認してください。rootCA-key.pem や dev-key.pem は転送・公開しません。[mkcert公式の説明](https://github.com/FiloSottile/mkcert#mobile-devices)
4. iPadの「設定 → 一般 → 情報 → 証明書信頼設定」で、作成したCAの完全な信頼を有効にします。設定名はOS版によって異なります。[Appleの手順](https://support.apple.com/ja-jp/102390)
5. 次のコマンドでLAN向けHTTPS配信を開始します。

~~~powershell
npm.cmd run start:https
~~~

6. Windowsファイアウォールで必要な場合は、プライベートネットワークに限りNode.js／TCP 5174の受信を許可します。iPad Safariで **https://192.168.1.20:5174/** を開きます（実際のIPに置換）。証明書の警告が出ない状態にしてください。警告画面を突破するだけでは検証条件を満たしません。
7. 「オフライン準備完了」を確認。Safariの共有メニューから「ホーム画面に追加」を選びます。「Webアプリとして開く」があるOS版ではオンにします。[Appleの手順](https://support.apple.com/ja-jp/guide/ipad/ipad8f1f7a29/ipados)
8. ホーム画面のアイコンから接続中に一度開き、そこで再度「オフライン準備完了」とマイク動作を確認します。その後、アプリを終了し、機内モード（Wi-Fiもオフ）で再起動して確認します。

IP変更時は証明書の再発行が必要です。初回未取得・サイトデータ消去後・OSによるキャッシュ削除後は再接続が必要です。開発用CAが不要になったらiPadからそのプロファイルを削除してください。証明書作成・インストールとファイアウォール設定は、この実装作業では実行していません。

## オフライン・更新の扱い

- 保存するのは public/ の固定アプリ資産だけ。音声・解析結果はCache Storage、IndexedDB、localStorageなどに書き込みません。
- 初回取得がすべて成功し、Service Workerがページを制御している場合に準備完了を表示します。
- 更新時には public/sw.js の CACHE_NAME の版を上げてください。新しい版は旧版のタブ／PWAをすべて閉じた後に有効になります。自動でマイク使用中の画面を差し替えません。
- 開発中に旧画面が残る場合は、Windowsの開発者ツール → Application → Service Workers で登録解除し、Cache Storageを削除して再読み込みします。アプリ音声の保存領域はありません。
- 独自サーバーの公開ルートは public/ の指定ファイルだけです。作業フォルダー全体や .certs/ を配信しないでください。
